# 공통 컨벤션

ui·api 모두 따른다. 각 프로젝트 전용 규칙은 `ui/convention.md`, `api/convention.md`에 둔다.

## 원칙

- 일반적인 관례로 작성한다.
- 성능·보안·유지보수성을 고려한다.

## 구조

- 최대한 짧고 단순하게 작성한다.
- 구현 전 기존 코드를 먼저 확인하고, 최대한 재사용한다. 같은 로직을 중복해서 만들지 않는다.
- 이미 작성된 코드와 일관성 있는 규칙을 따라 작성한다. 같은 개념은 같은 이름과 패턴으로 쓴다.
- 함수 래핑, 새로운 파일·클래스 생성 등은 반드시 필요할 때만 한다.
- 함수는 한 가지 일만 하고, 인자는 적게 둔다.
- 각 폴더·패키지는 자기 역할의 코드만 둔다.

## 네이밍

- 변수, 함수, 파일 등은 이름만으로 의도가 드러날 정도로 명확하게 짓는다.
- boolean은 is/has/can/should 접두어를 붙인다.

## 작성 규칙

- 조건은 단순하게 쓴다. 삼항은 1단계까지만, 복잡하면 변수로 뺀다.
- 문자열·경로·매직 넘버는 하드코딩하지 않고 상수로 분리한다.

## 주석

- 주석은 코드로 드러나지 않는 이유만 짧게 쓴다. 무엇을 하는지는 이름과 코드로 설명한다.

## 오류 처리

- 오류를 숨기지 않고, 정상 흐름과 오류 처리를 분리한다.

## 검증

- 변경한 동작은 테스트나 실행으로 확인한다.
